How to fix

[A]      Remove the opt-out and review the screens with Liquid Glass
         1. Delete the UIDesignRequiresCompatibility key from the Info.plist.
         2. Build with Xcode 27 and run the app on an iOS 27 simulator; the other findings in this
            report are the places to look at first.
         3. Keep the brand colour on tint (buttons, selected tab) rather than on bar backgrounds, so
            the system can draw the bars.
         https://github.com/muhittincamdali/glassready/blob/main/docs/guides/opt-out.md

[B]      Leave the header background to the system on iOS
         1. Set headerStyle.backgroundColor, headerBackground and headerBlurEffect only for Android
            (Platform.select) or for iOS before 26.
         2. Keep the brand colour on headerTintColor.
         https://github.com/muhittincamdali/glassready/blob/main/docs/guides/react-native-expo.md

[C]      Use the bar's measured height
         1. Remove the fixed height and read the height the navigator measures
            (useBottomTabBarHeight, useHeaderHeight) or the safe-area insets.
         https://github.com/muhittincamdali/glassready/blob/main/docs/guides/react-native-expo.md

[D]      Move to the native bottom tabs, or keep the JavaScript bar on purpose
         1. For the system tab bar, use createNativeBottomTabNavigator from
            @react-navigation/bottom-tabs/unstable (React Native 0.79 or later, react-native-screens
            4.30.0 or later).
         2. If the custom bar is part of the brand, keep it and check it next to the Liquid Glass
            headers on an iOS 27 simulator.
         https://github.com/muhittincamdali/glassready/blob/main/docs/guides/react-native-expo.md
